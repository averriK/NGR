## E1 knitBlock Source Context Repair

Trigger:

psha E26 proved that `NGR::knitBlock(vars = ...)` rewrites labels correctly but
does not make `vars` visible to R scripts sourced by child QMD chunks. psha QMD
builders rely on `source(file.path(root, "scripts", ...))` and those scripts
must see context variables such as `ID_TARGET` and `siteID_TARGET`.

Objective:

Make `knitBlock(vars = ...)` behave like a normal Quarto include from the
builder perspective: variables supplied through `vars` must be visible to child
chunks and to scripts sourced by those chunks, while prior values in
`knitr::knit_global()` are restored after the child finishes or errors.

Scope:

- `R/knitBlock.R`
- `tests/testthat/test-knitBlock.R`
- `dev/plan/quarto-yaml/active.md`

Out of scope:

- No qrt changes.
- No psha scaffold changes in the NGR repo.
- No docs/pkgdown rebuild in this repair unless the API contract text changes.
- No broad rewrite of label handling.

Plan:

1. Add a small internal helper that overlays named `vars` into
   `knitr::knit_global()` and restores previous bindings on exit.
2. Change `knitBlock()` to knit the child in `knitr::knit_global()` with that
   temporary overlay instead of in an isolated `list2env(vars, ...)`.
3. Add a test where a child QMD sources an R script and the script reads a
   variable supplied through `vars`.
4. Run focused `test-knitBlock.R`.
5. Install local NGR, then psha can retry AR-S2L1W `pptms.qmd`.
