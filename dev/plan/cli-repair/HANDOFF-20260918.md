## 3. Arquitectura de scaffolds (respuesta a «¿cómo se instalan los scaffolds arbitrarios?»)

Solo lo observado en esta sesión:

- No se «instalan». Un scaffold es un directorio con un `manifest.json` de fuente
  (`schemaVersion 1`, `id`, `resources[{from,to,ownership}]`, `artifacts`) y se
  consume en el lugar donde está con `ngr pull --from <ruta>/manifest.json`. El
  manifiesto del proyecto registra la ruta y los recibos por archivo bajo
  `scaffolds.<id>`. Verificado por `cli/tests/test_install.py:62-78`
  (`testRelocatedRuntimeHasNoCheckoutDependency`): tras `pull --from ngr yml`,
  `manifest.json` del proyecto apunta a `<prefix>/libexec/ngr/scaffold/manifest.json`.
- El único scaffold que el instalador copia es el del propio CLI (`cli/scaffold/`,
  alias `ngr`), porque forma parte del runtime instalado.
- El scaffold SHA vive en `/Users/averrik/Cloud/github/reports/sha` (sin git) y se usa
  con `--from /Users/averrik/Cloud/github/reports/sha/manifest.json`; R1 permite
  redirigir esa ruta a otra copia. UNKNOWN en esta sesión: si el propietario quiere
  que `reports/sha` pase a ser repo git (los renders muestran `Rev.—` mientras no lo sea).
